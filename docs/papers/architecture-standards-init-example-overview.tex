\begin{abstract}
\noindent
This repository is what the estate's generic template produces when it is run
against an empty repository: an Aspire composition root, a shared kernel with
mechanical guards on its scope, one service that owns its database and migrates
it from a hosted service, a Next.js product surface whose browser talks only to
its own origin, a container per service, a three-app Fly.io topology, and seven
workflows wired on the first commit. It exists to be read as an example of the
architecture rather than as a product. It carries no domain model, deliberately.
\end{abstract}

\section{What was built}

One bounded context, one service, one database, one screen. The smallest system
that exercises every principle rather than a demonstration of every guide at once.

\section{The decisions that were taken rather than defaulted}

Three of these the initializer asks about explicitly, because each is invisible in
the code and expensive to reverse. The rest were taken while building and are
recorded for the same reason: a year from now the question is not what was done,
but whether the alternative was considered.

\begin{center}
\begin{tabular}{@{}llp{7.4cm}@{}}
\toprule
\textbf{ADR} & \textbf{Decision} & \textbf{Why it is a decision and not a default} \\
\midrule
0002 & \texttt{fra} as the region & A volume is a local disk pinned to one region; moving it is a dump and restore, not a config edit \\
0003 & GHCR, mirrored into Fly's registry & A GHCR package is private by default and Fly cannot pull one; the mirror copies the manifest, so the same digest reaches both \\
0004 & No user accounts & A login page for a system with nobody to log in is scaffolding the first ticket deletes \\
0005 & PostgreSQL migrations only & EF keeps one snapshot per assembly, so two providers means two projects; nothing targets SQL Server \\
0006 & An evaluation-only Aspire API & Development-only, so the exposure is one edit to one file \\
0007 & A boot log as the vertical slice & The mechanism needs exercising; a product nobody described does not need inventing \\
\bottomrule
\end{tabular}
\end{center}

\section{How it ships}

\begin{figure}[htbp]
\centering
\includegraphics[width=0.9\linewidth]{../diagrams/rendered/a2-deploy-pipeline.pdf}
\caption{The tag-driven pipeline. Two rules in it are the ones most often missing.
A service whose Fly app does not exist is \emph{always} selected --- without it,
the first tag against an empty organisation deploys nothing at all, because
nothing has changed. And every gate accepts \texttt{success} \emph{or}
\texttt{skipped} from upstream --- without it, change detection and ordering fight
each other, and any unchanged service in the middle of the chain blocks everything
behind it.}
\end{figure}

\section{What it deliberately does not have}

Stated so that scope creep has something to fail against: no second service, no
event bus, no service mesh, no custom DI container, no abstraction over the
platform, no user store or token minting anywhere, and no sample domain model.
Each of those is a design decision with a reason when the time comes, not a
scaffolding default.
